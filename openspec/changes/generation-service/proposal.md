# Change: Сервис генерации (generation-service)

## Why

Нужен сервис, который принимает заказ на генерацию, списывает токены с баланса пользователя и передаёт задачу одному из фейковых провайдеров (`alpha` / `beta`). Если провайдер отказал — сервис идёт к следующему по цепочке «ног»; если отказали все — возвращает токены.

Ключевая сложность — надёжность денежных операций: каждое движение токенов (списание, возврат, начисление) должно происходить **ровно один раз**, даже при конкурентных вебхуках, повторной доставке одного и того же вебхука, дублирующихся оплатах, падении процесса посреди обработки и работе в нескольких воркерах одновременно.

## What Changes

- Новый сервис `generation-service` (FastAPI, async) с PostgreSQL как единственным источником истины (source of truth).
- Предметная область: пользователи с балансом токенов, журнал операций (ledger), каталог моделей с цепочкой «ног», задачи (tasks) и попытки (attempts).
- Публичный API: `POST /generate`, `POST /webhooks/providers/{name}`, `POST /webhooks/payments`, `GET /tasks/{id}`, `GET /users/{id}/balance`.
- Два фейковых провайдера `alpha` и `beta` с настраиваемым поведением отказов и вебхуками, подписанными HMAC-SHA256.
- Сторож (watchdog) для обработки таймаута провайдера (`PROVIDER_TIMEOUT`).
- Гарантии «ровно один раз» через уникальные ключи идемпотентности, транзакции и блокировки строк (`SELECT FOR UPDATE`).
- Миграции Alembic; `docker compose up` поднимает базу, сервис в 4 воркерах и обоих провайдеров.

## Impact

- Затронутые спецификации: новая capability `generation-service` (`openspec/specs/generation-service/spec.md` после archive).
- Затронутый код: новый пакет `src/` (handlers/routers/schemas/services/database/...), `Dockerfile`, `docker-compose.yml`, `alembic/`, `pyproject.toml`, `README.md`.
- Зависимости: PostgreSQL, uv, FastAPI + SQLAlchemy (async), gunicorn + UvicornWorker.
- Тесты: обязательные интеграционные (живой HTTP к compose с 4 воркерами + проверка БД) и юнит-тесты через ASGITransport.

## Non-goals

- Регистрация и авторизация пользователей.
- Пользовательский интерфейс.
- Настоящее файловое хранилище (результат — строка-ссылка).
- Настоящие деньги и платёжные системы.
- Идемпотентность `POST /generate` по `Idempotency-Key` (осознанно не добавляем — строго по ТЗ; фиксируем в README как «что можно улучшить»).
